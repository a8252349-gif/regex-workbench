Preguntas frecuentes

¿Cómo cambia caso positivo el resultado en Cómo probar una regex con varias cadenas?

Ejecuta ^[a-z][a-z0-9_-]{2,15}$ sobre regex_user, revisa caso positivo junto con caso negativo y compara el resultado exacto match. Conserva también las banderas y la semántica de JavaScript RegExp.

¿Por qué se mantiene (.*)* como contraejemplo?

Permite observar el modo de fallo. Compáralo con ^[a-z][a-z0-9_-]{2,15}$ sobre una entrada casi válida, localiza el primer falso positivo o falso negativo y explica la diferencia con caso límite y caso de regresión.

¿Qué caso límite pone a prueba falso positivo?

Elige un valor inmediatamente fuera del requisito y añade, cuando proceda, un salto, un carácter Unicode, un valor vacío o un delimitador extra. Debe existir una única razón clara para aceptar o rechazar.

¿Qué debe medirse antes de usar falso negativo con entradas largas?

Mide tiempo, número de coincidencias, truncado de resultados, presión de memoria y timeout del Worker. Una muestra corta y rápida no demuestra seguridad ante una cadena larga o hostil.

¿Cuándo conviene abandonar la expresión regular?

Usa un parser o una biblioteca de dominio cuando el anidamiento, los escapes, la validación semántica o la portabilidad sean más importantes que una coincidencia textual compacta.
